# Implementation decisions from the public-data audit

These notes record evidence-driven refinements to `PLAN.md`; numerical results belong in the executed report.

- VCM and ASR are independently initialized/trained. VCM preparation and training never load ASR or forced-alignment checkpoints.
- The SLURP real-audio archive transferred slowly, so audio comes from an immutable revision of `qmeeus/slurp`, checked against its LFS SHA-256 hashes. Original upstream recording IDs and annotations remain authoritative.
- The source annotation audit found microphone pairs crossing official partitions and one recording with conflicting transcripts. All affected recording views are removed, with exact IDs in `reports/leakage_quarantine.json`. Retained source partitions remain unchanged. Development/calibration grouping also preserves connected prompt/microphone families.
- A class enters the first VCM run only with at least 40 training examples and 10 development/calibration examples. This is a small-data inclusion rule, not a statistical adequacy claim. Missing classes are reported as unsupported. No alarm-to-timer relabeling is used.
- Verified word/parameter timestamps are absent. The first VCM is a causal classifier trained from utterance labels; early predictions are measured by replaying prefixes. Routing uses a stable trigger plus look-back. There is no trained boundary head or claimed phonetic boundary accuracy. A public-audio review queue is provided for future verified timing labels.
- The separate ASR starts with LibriSpeech and then adapts to human-transcribed SLURP assistant speech. Unverified token spans are not turned into fake parameter-crop training labels. Tail retention and parameter recognition are evaluated on predicted slices; a boundary-verified tail WER remains pending until such annotations exist.
- Acoustic ASR pretraining uses the original unmasked batch-padding baseline. Assistant adaptation masks invalid positions after the strided stem and each convolution block layer, so padding from a longer batch member cannot alter valid short-clip frames. The checkpoint records `mask_padding`; an explicit test compares single-clip and padded-batch outputs. This refinement does not import VCM weights or change the ASR label vocabulary.
- Assistant adaptation initially stalled on small feature-file reads (GPU utilization measured at 4%). After its first completed epoch, training resumes from the saved weights/optimizer with a 6,144 MiB maximum feature-array RAM cache. Exact restart records and the initial run configuration are preserved. Dataset/label order, model, loss, and schedule are unchanged; dropout RNG continuation is not promised bitwise identical after a restart.
- Initial augmentation is feature gain offset plus frequency/time masks. Controlled noise replay is evaluated separately. This run does not claim to have used recorded room-response augmentation.
- Only real Pi hardware measurements can satisfy Pi acceptance. Desktop CPU replay and microphone enumeration are labeled by actual host.
- Public Philippine English corpus access and usable task coverage must be established before any accent-specific result is claimed.
