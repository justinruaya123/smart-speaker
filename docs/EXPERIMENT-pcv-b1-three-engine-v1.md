Hypothesis: the development-selected mixed model improves exact finite commands across synthetic engines over the matched human-only model. Test results cannot select a model or policy. Synthetic-engine coverage is not original-human, microphone or Raspberry Pi evidence.

## Frozen design and execution plan

1. Freeze the 415 prompts and expected schema-v3 commands from qualification1: 93 baseline positives, 308 additional positives and 14 negatives. Use the reserved `test-gb-m` condition for each engine, giving 1,245 expected recordings. Qwen and Dia share an existing synthetic voice anchor; Parler uses its named Mike condition. Requested accents and spoken content are not independently verified.
2. Reuse only exact text-and-command matches from Qwen recordings already evaluated in this study's held-out corpus. Generate missing Qwen audio and all Dia/Parler audio into this version's cache. Do not access the other active study's sealed Dia audio. Preserve native and derived 16 kHz PCM, seeds, source/model/anchor hashes, waveform checks and retry receipts. No automatic model fallback or substitution for missing recordings.
3. Freeze source, checkpoint, catalog, normalization and disabled policy hashes before generation/inference. Generate sequentially to limit GPU memory alongside the unrelated Parler job: Qwen batches of two, Dia batches of two, verified Parler batches of four. Three waveform-only attempts for Qwen/Parler; twenty for Dia, matching its existing bounded retry policy. Never filter or regenerate based on VCM correctness. A waveform failure after the declared attempts remains a missing case in the denominator.
4. Audit all declared cells, duplicate PCM and overlap with training/development/calibration, retained waveforms and feature hashes. Preserve prior audio paths rather than copy reusable recordings. Extract complete-utterance features once, using the unchanged training frontend.
5. Evaluate both frozen FP32 CPU ONNX bundles once, with twelve exact decoder workers. Report each engine's 93 baseline cells, all additional positives and negatives, per-intent and per-slot results, raw candidates, the diagnostic threshold point, and actual policy outputs. Both parent policies remain disabled unless a separately versioned training/calibration study later qualifies them. All-reject is a failure to recognize commands.
6. Collate results here and in EXPERIMENTS.md, with compact machine receipts under `experiments/pcv-b1-three-engine-v1/` and audio/features/raw predictions under `.cache/pcv-b1-three-engine-v1/`. No commit, installation, physical action or unrelated-job changes.

This version uses the complete-utterance feature path. The parent strict waveform-streaming check failed numerical tolerance despite unchanged commands in every probe; that negative result is retained in the parent report. A future streaming frontend correction needs its own version and parity/calibration evidence.

## Findings

Preparation: ignore rules already protect the new cache while keeping protocol/report metadata visible. The 415-cell definition contains 401 positives and 14 negatives; one engine's repeated phrases are not independent human speakers. The three engines therefore supply 1,203 positive and 42 negative recordings, including 279 baseline recordings.

Pre-inference review confirmed all 415 unique prompt IDs, all 93 baseline text/command pairs, catalog consistency, all 117 Qwen reuse identities, no reuse overlap with fitting/calibration, and all 41 frozen bindings. One reporting defect was found: observed-only metrics could exclude missing generated positives. A separately bound [reporting-v2 protocol](../experiments/pcv-b1-three-engine-v1/report-v2-protocol.json) corrects this over unchanged predictions. Missing positives count as false negatives in overall, baseline, intent and slot denominators. Missing negative recordings make the false-accept rate unavailable, with explicit possible bounds and missing counts. The original evaluator and generation remain frozen. Seven targeted tests pass. [Review resolution](../experiments/pcv-b1-three-engine-v1/review-resolution.json).

Authoritative results will be `results-human-v2.json` and `results-mixed-v2.json`. Run `python scripts/test/pcv_three_engine_report.py` after the unchanged evaluator; this stage performs no acoustic inference or threshold selection. Original result files are preserved as intermediate evidence.

Qwen completed 415/415 cells: 298 new recordings and 117 exact held-out reuses. Its audit found no duplicate PCM, no non-test overlap, and matching native/audio/feature identities. No generation retries were recorded. [Qwen audit](../experiments/pcv-b1-three-engine-v1/qwen-audit.json).

Dia execution revision: the initial two-item run completed four recordings and logged two token-cap failures. With the unrelated Parler job still running, observed GPU use reached 15,738/16,376 MiB and the next attempt stopped making visible completion progress. Only this task's validated Dia processes (34392 and 34320) were stopped; the unrelated generator was untouched. Four finished waveforms and the original failure log are frozen. [Dia single-item protocol](../experiments/pcv-b1-three-engine-v1/dia-single-protocol.json) continues the remaining 411 phrases one at a time, releasing unused CUDA allocator cache before attempts. It preserves the FP32 model/codec, voice, token limit, temperature, twenty-attempt limit and all waveform checks. Batch membership and therefore remaining per-phrase RNG seeds change explicitly in this new revision. No VCM test inference or threshold change occurred. This is a resource-driven corpus-generation revision, not a claim of equivalent generated audio or a relaxed quality gate.

The single-item all-CUDA continuation reached 15 completed recordings, but again used 15,669/16,376 MiB system GPU memory and showed no completion for more than five minutes. Its completed files and failures are retained; only its validated processes (22120 and 17236) were stopped. The [CPU-codec revision](../experiments/pcv-b1-three-engine-v1/dia-cpu-codec-protocol.json) keeps the Dia acoustic generator on CUDA and moves DAC voice encoding/waveform decoding to CPU, preserving FP32 precision and all checkpoints, phrases, voices, sampling parameters and quality gates. CPU/GPU rounding can change voice codes/audio, so numerical equivalence of generated speech is not claimed.

Two development-voice preflight phrases passed on their first attempts in 7.26 and 13.29 seconds. Peak CUDA allocation was 6,808,579,584 bytes and reservation 6,905,921,536 bytes, versus the prior observed 10,041,163,776-byte reservation. These are resource/waveform checks, not listener or VCM accuracy evidence. [Preflight](../experiments/pcv-b1-three-engine-v1/dia-cpu-codec-preflight.json). An [output adapter](../experiments/pcv-b1-three-engine-v1/dia-cpu-output-protocol.json) places mutable continuation manifests/features/logs in a new cache directory, preserving frozen predecessor logs. The first 15 CUDA-codec recordings remain in the final declared corpus with their original provenance.

The CPU-codec continuation reached 67 completed recordings. Repeated generations without an end marker still consumed the original 1,600-token allowance. A separately frozen [duration-bound revision](../experiments/pcv-b1-three-engine-v1/dia-bounded-protocol.json) retains all 67 recordings and uses `ceil(12 * 44100 / 512) + 16 = 1050` new tokens, derived from the existing 12-second waveform limit, DAC sample rate/hop and a delay/stop allowance. Independent waveform duration and end-marker checks remain required. Both predetermined development probes produced identical native WAV, derived WAV and decoded PCM hashes at 1,600 and 1,050 tokens. This [two-probe result](../experiments/pcv-b1-three-engine-v1/dia-bounded-preflight.json) does not establish equivalence for every random generation. All previous logs are preserved and no VCM test result was consulted. Progress is recorded under `.cache/pcv-b1-three-engine-v1/dia-bounded-v1/status.json`.

All three TTS engines run locally from downloaded checkpoints. Dia uses this Windows machine's GPU for acoustic generation and its CPU for the audio codec; moving the codec does not introduce a cloud service. The separate Parler experiment shares the GPU and remains untouched.

The [completion controller](../experiments/pcv-b1-three-engine-v1/completion-controller-protocol.json) binds its source and all execution revisions before inference. It waits for this task's exact Dia process identity to exit with a completion receipt, then runs Parler, assembly/audit, a generation-lineage freeze, both existing evaluators and reporting-v2 sequentially. A failed subprocess stops later stages. Its status is `.cache/pcv-b1-three-engine-v1/completion-controller-status.json`; this is continuation of the current test, with no additional training or policy change.
