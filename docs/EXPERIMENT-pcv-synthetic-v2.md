## Evaluation bottleneck diagnosis, 2026-10-01

The user asked why overall CPU usage was about 3%. A four-second sample of live worker 14928 measured 0.959 CPU-core equivalents, or 3.00% across 32 logical CPUs (24 physical cores). One thread accumulated 3.875 CPU seconds while other sampled threads accumulated none; all 32 logical CPUs were allowed by affinity. No disk reads occurred. A concurrent GPU snapshot reported 0% utilization; this is a momentary observation, not an average over training.

A separate diagnostic process loaded the completed seed-53 epoch-16 checkpoint and six already-scored development recordings, one per engine and phase. All six typed outputs matched the saved development outputs. The catalog contains 2,768 phrase entries and 30,424 prefix nodes. The exact decoder iterates over audio frames on CPU with NumPy `logaddexp` updates; development processes one recording at a time. The model already runs on CUDA. This serialization, not a Pi CPU cap or restricted process affinity, explains the low aggregate utilization.

| Stage | Total across six diagnostic clips | Per-clip range |
| --- | ---: | ---: |
| CUDA model forward, synchronized | 35.6 ms | 0.6-7.7 ms |

| CPU exact CTC catalog scoring | 2,401.4 ms | 136-939 ms |
| CPU complete-command ranking | 49.6 ms | 8.0-8.5 ms |

CPU catalog scoring plus ranking accounts for approximately 98.5% of these measured stages. Profiling also counted 16,608 repeated canonical JSON serializations across the six clips; that is a smaller overhead than the CTC scoring itself. These are diagnostic timings on this host under concurrent load, including profiler overhead, not the final speed benchmark or Pi measurements.

Accuracy-preserving acceleration candidates are worker parallelism across independent recordings, a batched GPU implementation of the same exact decoder, and cached canonical command keys. Raising Torch's thread setting alone does not parallelize the current NumPy/Python decoder. No acceleration change was injected into the frozen run, no test data was accessed, and no beam pruning, shorter catalog, skipped evaluation or relaxed criterion was introduced.
