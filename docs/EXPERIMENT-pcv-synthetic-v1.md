# PCV synthetic v1: exact and natural-sentence command benchmark

## Scope and authorization

The 2026-09-30 user request explicitly replaces human voice acceptance for this study with synthetic speech from at least three large TTS models, multiple English accents per verbatim, model improvement, ONNX Runtime benchmarking, and exact versus natural-sentence phases. This is a new synthetic experiment addressing ME-02/03/04/06/08 and UC-01 through UC-10. It does not modify the human-only PC-v1 protocol or claim human or physical-Pi acceptance. The user explicitly confirmed that “onit” means ONNX Runtime.

Use the current branch and root Python environment; preserve unrelated dirty research and installed artifacts. New source and compact receipts live in `experiments/pcv-synthetic-v1/`, large generated audio, models, features and checkpoints in `.cache/pcv-synthetic-v1/`. Existing committed ignore rules cover the payloads and expose the experiment metadata. No cleanup, external actions or publication is in scope.

## Frozen design

Phase 1 retains all 570 positive and 200 rejection verbatims of PC-v1. Phase 2 adds two explicitly enumerated natural-sentence variants per verbatim, mapped to the identical typed command or rejection. This is finite paraphrase coverage, not unrestricted natural-language understanding. Freeze the verbatim list and generation assignments before fitting. The original contract and model architecture remain unchanged; the synthetic decoder receives a separately versioned catalog extension.

Three distinct TTS families are Qwen3-TTS 1.7B (existing VoiceDesign creates original voice anchors; Base synthesizes utterances), Parler-TTS Large v1 2.2B, and Dia 1.6B. Public primary sources: [Qwen](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign), [Parler](https://huggingface.co/parler-tts/parler-tts-large-v1), [Dia](https://huggingface.co/nari-labs/Dia-1.6B-0626). Download revisions and full asset hashes, including tokenizer binaries, are retained in [sources](../experiments/pcv-synthetic-v1/tts-sources.json) and [assets](../experiments/pcv-synthetic-v1/tts-assets.json). Qwen and Parler fitted together in the RTX 4080 SUPER pilot at approximately 11 GB VRAM; the orchestrator runs them concurrently, followed by Dia alone. Recognition training and CPU timing follow synthesis. TTS models are offline dataset-generation tools and are excluded from deployed VCM inference.

For each of 2,310 verbatims, use six voice groups per TTS family: two training, one development, one calibration, two final test. This yields 41,580 planned clips, including six final test clips per verbatim (two per TTS family). English accent requests include American, British, Australian and Indian English. Synthetic voice/seed identities are not independent humans. Dia may condition on original Qwen-designed anchors; record this dependence and keep each anchor group confined to one split across all generators. Accent labels are requested conditions until independently checked, never asserted as verified.

Retain native generated audio and derived mono 16 kHz PCM. Audit finite samples, duration, clipping, silence, file and decoded-PCM hashes, duplicates and split leakage. Failed generation remains in the denominator and failure log. No silent removal, word splicing or ASR verification. Prescribed text is an intended synthesis label; audio-content fidelity remains unverified without listening. A generation pilot measures throughput before the full run; it is not benchmark acceptance.

## Model and evaluation

Reuse the causal 113,064-parameter CNN, causal 40-bin frontend, finite CTC decoder, endpoint and acceptance predicate. Audit retained project-trained checkpoints before any continuation; otherwise declare random initialization. Never import a pretrained general speech recognizer. Fit normalization using training audio only. Select checkpoints with development data only. Freeze the selected model before calibrating score/margin thresholds on calibration data. Seal final test assignments before fitting and retain their first evaluation. Later test-driven revisions require a new benchmark version.

Report exact typed-command recall, accepted precision, intent accuracy, parameter errors, rejection false accepts and coverage per phase, use case, verbatim, TTS family and requested accent. Report zero denominators as unavailable. Model improvement means a measured development comparison followed by a locked final evaluation, not a guarantee that every phrase will pass. Calibration targets retain 99% accepted precision, 90% positive recall per phase/engine/use case and <=1% negative false accepts; unmet targets disable acceptance and remain failures. Precision includes incorrect commands emitted into a use case from other reference categories. Capture failures are invalid trials, never successful negative rejections. Software, synthetic audio and physical hardware results are separate.

ONNX validation must load the selected graph in CPUExecutionProvider, check nonzero streaming caches and waveform decision parity, and benchmark the same frontend/decoder/endpoint/policy used for inference. Record graph, catalog, normalization, endpoint, policy, manifests and source hashes. Store raw prediction rows and failure lists. No model installation or production qualification follows automatically from this synthetic study.

## Implementation and verification plan

1. Test-first deterministic verbatim expansion, typed-output preservation and disjoint generation assignments; freeze full machine-readable and human-readable lists.
2. Acquire pinned TTS dependencies/models without changing the shared environment's existing versions; run native-audio pilots for all three engines and retain receipts/failures.
3. Generate and audit complete split-specific audio with resumable immutable receipts and explicit missing counts.
4. Train/continue the existing CNN with isolated outputs, development selection and calibration; export selected graph and verify ONNX parity.
5. Run both benchmark phases on the sealed synthetic test split, report all strata and failed cases, and review the complete experiment diff.

## Execution ledger

- Initial state: historical PC-v1 infrastructure exists, but no trained PC-v1 bundle or original PC-v1 recordings exist. Synthetic generation is now explicitly authorized. The old human recording blocker does not block this new study.
- Hardware inventory: RTX 4080 SUPER, 16 GB VRAM; about 102 GB free at start. Qwen uses existing local checkpoints. Parler Large, Dia and the DAC codec downloads completed with pinned revisions. Parler needs Transformers 4.46.1, so its libraries are isolated in `.cache/pcv-synthetic-v1/parler-site` and run with the root interpreter. Existing root package versions were preserved. The [environment receipt](../experiments/pcv-synthetic-v1/environment.json) records actual versions; the isolated dependency set is not claimed to be a fully resolved lock.
- Before fitting, a wording audit found four elliptical media commands that needed grammatical expansion. Preserved r1 verbatims/protocol and an explicit amendment under `revisions/`; r2 changes eight phase-2 rows. Previously generated audio is reusable only where the complete reference record is identical. No affected row had been synthesized.
- Preserved 24 padded Parler pilot clips under `.cache/pcv-synthetic-v1/parler-padded-pilot/`. The repaired adapter uses returned EOS sample lengths, not signal-level trimming. The corrected corpus had 176 Parler clips and 880 Qwen clips before the full-run restart.
- Dia temperature 1.0 produced near-silent, cap-length output. A controlled single-utterance comparison reproduced that failure in FP32; temperature 1.8 (the published default) produced normal-level output. Moved DAC decoding to CUDA and selected FP32 for Dia. The 12 failed initial clips remain under `dia-temperature1-pilot/`. Twenty subsequent unpunctuated clips remain under `dia-unpunctuated-pilot/`; neither directory belongs to the active corpus. Generation probes are excluded from fitting and acceptance.
- Dia now appends a terminal period where punctuation is missing, preserving all spoken words. It rejects forced token-cap endings. The final six-voice pilot generated 24 valid clips in 237 seconds; three batches needed a retry. Before fitting, the full-run generation bound was set to 20 deterministic attempts per Dia batch (three for Qwen/Parler), with an explicit recipe amendment and unchanged successful-pilot audio receipts. This throughput suggests tens of GPU hours for exhaustive synthesis, rather than a short smoke test. This is generation quality control, never selection by VCM predictions. Each attempt/seed and error is retained. Parler uses named-voice descriptions rather than Qwen audio anchors; the initial Parler metadata clarification is preserved under `revisions/`. Corpus-wide synthesis has not yet completed; a successful pilot does not establish speech-content or accent fidelity.
- The continuation baseline is the existing project-trained seed-71/epoch-18 causal CNN, initialized originally from random weights. Checkpoint and graph arrays/phone order match, but the historical ONNX graph failed the fixed nonzero-cache numerical gate at 17 frames: maximum absolute error 2.6702880859375e-5 versus required <2e-5. [Baseline receipt](../experiments/pcv-synthetic-v1/baseline.json). This is an unqualified baseline, not a production graph. The synthetic candidate must independently pass export/cache and full-development waveform parity.
- The endpoint is fixed at -45 dBFS with 300 ms minimum speech, 700 ms trailing silence and 12 s maximum capture. Replay explicitly appends 800 ms of silence; timings exclude audio-file reads and speaking duration, and report the endpoint wait separately.
- Fresh verification on 2026-09-30: 113 tests passed across the 91 PC-v1 cases and 22 synthetic cases. The 1,080 completed clips passed file/PCM/provenance and duplicate checks; this is a partial corpus audit, not acceptance. Twenty installed artifact hashes remain unchanged. No synthetic model fitting, measured improvement, final ONNX test score or production pass has been recorded at this point.

## Running and inspecting the authorized study

The full list of verbatims and exact expected JSON is [PCV-SYNTHETIC-VERBATIMS.md](PCV-SYNTHETIC-VERBATIMS.md). Expectations are not observed outputs. The resumable per-engine generators verify audio, model/config/tokenizer identities and the frozen assignment before writing new clips.

```powershell
.venv/Scripts/python.exe experiments/pcv-synthetic-v1/run.py status
.venv/Scripts/python.exe experiments/pcv-synthetic-v1/orchestrate.py --job .cache/pcv-synthetic-v1/jobs/full-run-20260930
```

Run the orchestrator once, only after all pilot processes have exited. It records each child PID, command, log and exit code in its job directory; it stops on generation, integrity, export or parity failure. The complete sequence is generation -> corpus audit -> baseline development measurement -> two 40-epoch continuation runs -> development selection -> ONNX export -> waveform parity -> calibration -> sealed final test -> report. The final-test reservation is exclusive; interrupted or failed test access remains recorded rather than being silently repeated. Do not change source files while a full job is running.

On completion, `.cache/pcv-synthetic-v1/report/` contains `benchmark.md`, `all-verbatims-with-outputs.jsonl`, `demo-outputs.json`, `failed-verbatims.json` and `metrics.json`. Each observed output references its retained audio, requested accent and engine. Until those files exist, the benchmark is incomplete. An enabled synthetic policy, human acceptance and physical Pi readiness remain separate statuses. The orchestrator never installs or publishes the candidate.
